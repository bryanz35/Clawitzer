- [x] Actuator identities: DS3235 base; TMC2209 + motor-shaft AS5047P elbow; differential MS62 wrist; MS62 gripper.
- [ ] Tune the elbow following tolerance (`set following`, currently 2°) against real motion; too tight will trip `following_error` on backlash. All calibration measurements are compiled into `board_config.h`, so a fresh flash validates: base (1500 µs, −5.555555 µs/deg), 1:2 differential wrist, gripper 970–2500 µs / 1735 µs center, 200 full steps/rev at 1/4 microstepping, 21:1, directions +1, 1700 mA RMS, 0.11 Ω, following 2°. **Guarded auto-reference**: `reference` stores the motor-shaft angle in NVS (`homeRaw`, record v3), and boot re-references automatically only when the encoder still reads that angle within 256 counts (~0.27° of elbow); otherwise the manual marked-home path stays. NVS still overrides mappings for re-measurement.
- Base mapping update (2026-11-07): DS3235-180 assumed, 500–2500 µs, 1500 µs straight forward (`j1=0°`), joint travel = 2× servo travel (±180° base). User measured 1000 µs at +90° CCW viewed from above (12 → 9 o'clock). Fresh calibration now uses −5.555555 µs/joint-degree; measured NVS mappings take precedence. The user bench-tested the **full ±180° travel** (both 500 and 2500 µs ends) and the direction; the measured 11.111 µs per *servo* degree already pins the 180° variant. No joint limits changed.
- Wrist calibration (2026-11-07): straight `(1500,1500)`, +90° pitch-down `(500,2500)`, pitch-up collision stop `(2200,800)`, roll ±90° at `(2500,2500)` / `(500,500)` (CCW/CW viewed from elbow toward gripper = logical ∓90°). All five poses fit the existing 1:2 differential exactly: `A = 1500 − 11.1111(roll+pitch)`, `B = 1500 − 11.1111(roll−pitch)`; fresh firmware defaults use it. The −63° up stop is a **collision** limit, not a servo stop, so j3's URDF lower limit is now −63° (regenerated) while roll may still move there. Reachable region is the diamond `|j3|+|j4| ≤ 90`; `Arm` projects commanded poses onto it and `save` validates the diamond clipped by the j3/j4 limits. Verified by a new actuator test and an Arm projection test (diamond vertex, unreachable corner, collision-stop roll); 55 native tests, 63 vitest, typecheck and the ESP32 build pass. Not flashed.
- Gripper mapping (2026-11-07): measured closed 970 µs / open 2500 µs map to logical j5 −90°/+90°, yielding center 1735 µs and +8.5 µs/logical-degree. Fresh defaults use this mapping; code-owned gripper window is narrowed to 970–2500 µs. Runtime smoke exercised mapping plus raw bench rejection below/above endpoints; 53 native tests, NodeMCU-32S cross-build and tools typecheck passed. Not flashed; physical observations are user-supplied.
- Camera servo (j6, 2026-11-07): user reports **1:1**, 180° travel over 500–2500 µs, so **90° = looking forward** (1500 µs) and **+11.111 µs/degree**. That is the opposite sign to the base (−5.5556), matching the mount that turns CW where the base turns CCW. The firmware's existing 0–180° → 500–2500 µs mapping already matches, so only the convention is documented; endpoints remain unmeasured mechanically. Adjustable only by reflashing `board_config.h`.
- Encoder fault tolerance (2026-11-07): implausible shaft jumps are discarded without touching the count (no silent reference shift), following/limit/read faults latch only after 5 consecutive bad samples (~50 ms), and up to 5° past a joint limit is tolerated without counting as following error. Verified by three new native tests (glitch ignored, sustained read fault still latches, 3° overshoot tolerated vs a real excursion latching); 59 native tests and the ESP32 build pass. Not flashed. Gearbox ratio **21:1** is confirmed by the mechanical engineer and by a bubble-level check: `step 500` (0.625 motor rev) moved the elbow ~10.5° against 10.714° predicted (−2%; implied 21.43:1, ±0.5° spans 20.45–22.50). The earlier 90–100° estimate was wrong; that trial is 80.36°. The team bench-tested the reverse direction and accepted 1700 mA / 0.11 Ω as the driver configuration.
