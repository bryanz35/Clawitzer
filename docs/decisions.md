# Decisions

Changes to the first nine rows need the team's agreement (see root `CLAUDE.md`).

| date | decision | why |
|---|---|---|
| 2026-11-06 | WebXR in Quest Browser, not a native Unity/Unreal app | No build/sideload loop; same TS stack as the rest; fast iteration in a 36 h hackathon. |
| 2026-11-06 | Plain HTTP. The Quest uses the `unsafely-treat-insecure-origin-as-secure` flag for the operator origin | Certificates on a phone-hosted LAN server cost time and break easily. No HTTPS/mkcert tooling. |
| 2026-11-07 | The phone side is a native Android app (Kotlin + Compose) with an embedded HTTP + signaling server. Replaces the 2026-11-06 "phone page loads from `localhost`" + Termux server. | One install instead of Termux + Node + Chrome. Native camera, USB host and sensors avoid WebUSB claim issues and web-serial-polyfill. Operator and wire protocols are unchanged. |
| 2026-11-06 | No Bluetooth path to the Quest; the IMU wearable uses `ws://` | Web Bluetooth is not usable in Quest Browser. |
| 2026-11-06 | Three.js only (no Babylon.js, no IWSDK) | closed-chain-ik is built on Three.js. |
| 2026-11-06 | IK uses closed-chain-ik `Solver` on the main thread, never `WorkerSolver`. Goal = position + 2 orientation DOF; sacrificed axis TBD (recorded in `arm.urdf`) | `WorkerSolver` needs SharedArrayBuffer, which Chromium on Android lacks. A 5-DOF arm can't match a 6-DOF hand pose. |
| 2026-11-06 | Hybrid tracking: Quest hand/body primary, IMU wearable fallback | Body-tracking elbow poses can drop out or be low-confidence. |
| 2026-11-06 | Video: wide-FOV capture on a world-locked panel; crop offset = head − phone orientation; WebRTC, never MJPEG | Cropping hides pan/tilt lag; the phone sensor gives the true camera pose; WebRTC has far lower latency and bandwidth. |
| 2026-11-06 | Phone → MCU over USB serial (fallback: Wi-Fi WebSocket to the ESP32). 2026-11-07: via Android USB host + usb-serial-for-android instead of WebUSB. | Wired is lower latency and more reliable than venue Wi-Fi. The fallback covers the app failing to claim the USB interface. |
| 2026-11-06 | Scaffold: closed-chain-ik goals constrain all 3 rotations or none, so the IK appends an unlimited virtual joint about the sacrificed axis and closes to a full 6-DOF goal | Only way to express "position + 2 orientation DOF" with this solver. |
| 2026-11-06 | Scaffold: added a `peer {role, present}` signaling message, sent by the server | Lets the operator re-offer when the phone reconnects. It is transport presence, not business logic. |
| 2026-11-06 | Scaffold: status-line `seq` = last command seq the MCU accepted; hosts resync from it on connect and on `HOMING` | Implements the "re-handshake on reconnect" rule without a separate handshake message. Keeps the strict non-increasing-seq drop. |
| 2026-11-06 | Scaffold: home pose and acceleration limits live in arm.urdf as `<arm_mirror home acceleration>` inside each `<joint>` | Standard URDF has neither. The firmware needs both, and arm.urdf is the single source of truth. |
| 2026-11-06 | Scaffold: IK rejects (holds) any solution with a per-frame jump > `MAX_JOINT_STEP_DEG` instead of rate-limiting toward it | Safety invariant 6 says reject. The operator sees "align your hand with the blue arm". Revisit if it feels too sticky. |
| 2026-11-07 | Android app dependencies: Ktor (server-cio, websockets), io.getstream:stream-webrtc-android, com.github.mik3y:usb-serial-for-android (JitPack), Jetpack Compose | Prebuilt libwebrtc without an NDK build; Ktor is the smallest maintained embedded HTTP + WebSocket server; usb-serial-for-android handles CDC-ACM. |
| 2026-11-07 | Arm controller uses ESP-IDF through PlatformIO, without Arduino or ESP32Servo; pinned Nix FHS development shell | User-requested framework cutover. Portable `Arm` owns safe articulation, LEDC supplies PWM, and USB Serial/JTAG preserves the existing serial protocol. |
| 2026-11-07 | Actual controller is NodeMCU-32S / ESP-WROOM-32, not ESP32-S3; keep ESP-IDF and use UART0 through its USB bridge | User hardware clarification. GPIO6..11 are flash; GPIO34..39 have no internal pulls. Code-owned pins avoid boot straps and reserve GPIO1/3 for host serial. Phone CDC-ACM polyfill compatibility remains an explicit blocker, not an assumed working path. |
| 2026-11-07 | Mixed hardware maps j1 DS3235, j2 TMC2209, differential j3/j4 MS62 pair, j5 MS62 gripper; exclude gripper from pose IK | User-specified actuators. Preserve five protocol coordinates without inventing wrist yaw or changing joint limits. |
| 2026-11-07 | Pins, e-stop polarity and hard pulse windows are code-owned in `board_config.h`; NVS stores only discovered mappings. The long setup wizard is replaced by `wrist` direct A/B jogging | User asked for quick wrist differential exploration and code-configured wiring/endstops. Serial hardware edits are rejected and loaded records cannot restore wiring. Assumed 500–2500 µs windows are placeholders, not measured travel. |
| 2026-11-07 | User-approved guarded bench calibration exception; no automatic sweeps | Disconnected/unloaded linkage, physical e-stop, exact consent, isolated arming, small explicit jogs and a 200 ms keepalive lease. Normal J commands remain blocked; complete generated-limit envelope validation precedes save. |
| 2026-11-07 | Motor-shaft AS5047P requires manual generated-home reference after every reset/power loss/e-stop/fault; monitor following error without automatic correction | A single-turn motor reading is ambiguous through reduction. Never guess the output-joint turn index or silently resume after actuator power loss. |
| 2026-11-07 | Drop the in-VR 3D arm copy (digital twin); remove `twin.ts` and the operator's `urdf-loader` dependency | Team decision: the video panel shows the real arm and the HUD shows commanded/reported state. `urdf-loader` stays in `packages/kinematics` as closed-chain-ik's peer dependency. |
| 2026-11-07 | Adopt mechanical's arm answers (`docs/questions.md`): URDF angles re-centered on their home pose (their j1 180°, j3/j4 90° → 0); j3 = wrist pitch, j4 = wrist roll (differential output order, swapped from the earlier roll/pitch); j2 safe range read as 90° up / 20° down with positive = down (-90…+20°); IK `freeAxis` = "z" (hand swing dropped; j1 supplies left/right) | User-approved interpretation of ambiguous answers. Velocity/acceleration stay at placeholders until mechanical answers. |
| 2026-11-07 | Clutch (relative) hand mapping replaces the absolute knuckle-relative-to-body-elbow mapping; solved angles shown in the in-VR HUD only; no gripper gesture yet | Works with Quest hand tracking alone (IWER and real dropouts had no elbow, so IK never ran), anchors on the arm's current tool pose so engaging never trips the step check, and uses head yaw at engage so turning your body doesn't rotate the arm. An IMU hand pose can later feed the same clutch. |
| 2026-11-07 | Bring back an in-VR arm model as a debug-only view, toggled by a phone-app switch (`debug {on}` on the control channel) | User request. Primitive bars from the parsed `arm.urdf` chain, no `urdf-loader`/mesh in the operator; off by default, so the earlier drop decision still holds for normal operation. |
| 2026-11-07 | Bring back the absolute elbow-relative mapping as an `elbow` mode beside the clutch, chosen in the phone app (`track {mode}`); blends in over 1.5 s from the arm's pose at engage | User request: compare accuracy. Body translation cancels and re-pinching can't drift; the engage blend fixes the old version's step rejection. The clutch stays the default because IWER and elbow dropouts give no elbow. |
| 2026-11-08 | Deadman becomes middle/ring/little fingers curled; thumb–index pinch drives the gripper position (squeeze harder = command past contact). Release only on clearly extended fingers or >500 ms tracking loss; half-curl keeps state. Gripper ramps at the j5 URDF velocity limit. Palm-toward-head check dropped from the deadman | User request: pinch needed for the gripper, avoid false releases from tracking uncertainty. Arm still holds while the hand is missing (invariant 5); the grace period was the user's choice over never/immediate release |
